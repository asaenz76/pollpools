# Social Experience (Phase 5)

Creator following, an activity feed, idempotent notifications, public profiles
with prediction history, sharing, and likes/comments behind feature flags.

## Feed

`feed_activities` is populated by **triggers** (never trusts the client), deduped
on `(tenant_id, dedupe_key)`. Activity types: creator published an event, user
submitted a prediction, user earned an achievement, event settled. The feed query
batch-resolves creator/event/profile names and renders a public, non-sensitive
line per activity.

## Notifications (idempotent)

`notifications` are generated by triggers on the source events, always deduped on
`(tenant_id, dedupe_key)` so **settlement retries and regrades never duplicate**:

| Trigger | Notification | dedupe key |
| --- | --- | --- |
| `settlement_grades` insert | `prediction_correct` / `prediction_incorrect` | `pred:{prediction}:{version}` |
| `user_achievements` insert | `achievement_earned` (+ feed) | `ach:{id}` |
| `creator_follows` insert | `creator_followed` (to creator owner) | `follow:{id}` |
| `events` publish | `new_creator_event` (to followers) | `new_event:{event}:{user}` |
| `competitor_draft_assignments` confirmed | `draft_confirmed` | `draft_conf:{id}` |

A regrade creates a **new** grading version → a new corrected notice (intended).
RLS: a user reads and marks read only their own notifications. The header + bottom
nav show an unread badge.

## Following & profiles

`creator_follows` (unique per creator+user). The creator profile shows follower
count + a Follow button (behind `creator_following_enabled`); the tenant is derived
server-side from the creator, never client-supplied.

Public profiles show stats, achievements, and **prediction history**. Since
individual predictions are owner-only under RLS, history comes from the
`public_user_history` SECURITY DEFINER function, which returns only **settled**
predictions (no pre-lock pick leak) and only when the profile is public.

## Sharing, likes, comments

- **Sharing** (`sharing_enabled`): Web Share API with clipboard fallback.
- **Likes** (`likes_enabled`) and **comments** (`comments_enabled`): gated in the
  UI **and** re-checked server-side in the actions (`toggleLikeAction` /
  `addCommentAction` read the tenant flag before writing). Likes are unique per
  user+subject; comments are RLS-scoped (visible to all; author edits own; admin
  moderates).

## Navigation

Mobile-first bottom navigation (`BottomNav`) for signed-in users: Home · Feed ·
Ranks · Alerts (unread badge) · You (`/me` → own profile).

## Tests

`social.test.ts` (integration): settlement notifies each predictor exactly once,
a settle retry doesn't re-fire, regrade adds one corrected notice, achievement +
follow notifications (follow deduped by unique constraint), feed generation, and
notification RLS (a user reads only their own).

## Deferred hooks

Draft notification types are defined and `draft_confirmed` is generated; the
remaining draft notices (closing soon, rank changed, prize awarded) and streak/
leaderboard-milestone notifications are wired as the relevant jobs land.
